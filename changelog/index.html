2.0

10 November 2026

A release for macOS 27 and for judging the borderline cases, on GitHub.

  • A detail panel beside every list. Select a row and click Details in the toolbar, or press Option-Command-I, to see the full path, why the file is listed, which installed apps it was compared against, its size and date, and how it will be removed, with buttons to reveal it in Finder or copy the path. A leftover of the same vendor shows that vendor's apps that are still installed; a leftover nothing claims shows how many apps, helpers, Homebrew packages and command-line tools it was held against.
  • Clean lists older simulator runtimes: every runtime image simctl is allowed to delete, except the newest one of each platform, with its size and when it was last used. On a Mac that builds for iOS they are often the largest developer files, around eight gigabytes each. A runtime image cannot go to the Trash, so Debris deletes it through xcrun simctl runtime delete. None is selected for you, and the confirmation says that they cannot be put back. Xcode downloads a runtime again under Settings, Components, and simulators made for a deleted runtime show up under Unavailable simulators on the next scan.
  • The summary after a removal shows how much went to the Trash and the size of each item, says that the space only comes back once the Trash is emptied, and has a button that opens the Trash.
  • On macOS 27 Debris said it had no Full Disk Access even with the switch on, because the file it checked no longer exists there. It now checks the system's privacy database, with the Safari and Mail folders as a fallback. It also checks again whenever you come back to it, so returning from System Settings is enough, and a scan made without access runs again once access is there.
  • The explanation under each rule in Clean sat in the section header, which keeps the height it was first given. When the list got narrower or wider, the text was cut off or left an empty gap. It is now the first row of the section and follows the width.
  • Built with Xcode 27.2 against the macOS 27 SDK. It still runs on macOS 15 and later.

1.0.1

13 September 2026

A fix release for the Leftovers scan, on GitHub. Four kinds of file were listed although their owner was still on the disk:

  • Preferences that a Qt app writes under its own name, such as com.raspberrypi.Raspberry Pi Imager.plist, were graded as a vendor match and listed as possibly left over while the app was installed. The name of an installed app now outranks the vendor. Only the names of apps and Homebrew packages count, not those of the helpers embedded in them, which tend to be called Helper or Widgets.
  • Command-line tools installed outside Homebrew, with pip or a downloaded installer, were unknown to the scan, so their folders in ~/.cache, ~/.config and ~/.local/share were listed. Executables in the Homebrew, /usr/local, ~/.local/bin, ~/.cargo/bin, ~/go/bin and ~/bin directories now own the folders that carry their name.
  • Apps that ship inside another app's node_modules folder, such as Codex Computer Use inside ChatGPT, were not seen, so their caches and preferences were listed. The folder is now read inside app bundles, for a fraction of a second on a scan.
  • The node-gyp cache in ~/Library/Caches was listed as a likely leftover while node was installed. It belongs to node.

1.0

8 September 2026

The first release, on GitHub as a disk image you drag to Applications.

  • Leftovers: files that belong to apps you no longer have, grouped by app, each with a reason.
  • Uninstall: everything an installed app owns, removed in one go, including files the system owns after an administrator prompt.
  • Clean: caches, logs, developer artifacts and installer files, each behind a rule that says what it keeps.
  • Rescan in every module, an app icon, and a Full Disk Access banner that explains what it is for.
  • Signed with a Developer ID and notarized; everything goes to the Trash, nothing is deleted outright.
